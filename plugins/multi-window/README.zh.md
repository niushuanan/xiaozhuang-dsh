# @deepseek-ai/dsh-client-ui-multi-window

[English](README.md) | 中文

DSH 原生多对话分屏插件。启用后，会话行的 `…` 菜单会在“重命名”“分叉会话”“归档会话”之后增加“并排打开”。所选对话会直接成为当前页面里的另一块工作区，不再弹出操作系统窗口或浏览器窗口。

启用本插件后，分叉默认进入对照工作状态。无论用户从目录中的对话行发起“分叉会话”，还是从对话里的某个已完成回合发起分叉，DSH 都会保留原对话作为主块，并把新分支直接放到旁边。两个入口共用同一个原生对话服务；关闭插件后会自然恢复普通的单对话跳转。如果页面已经达到四块上限，成功创建的分支仍会正常打开，不会无反馈地消失。

用户也可以把目录里的对话直接拖到对话页面。整个对话区域会变成距离近、状态明确的接收面，松开后把该对话作为副块打开。这是一次“复制到分屏”的展示操作，不会误触目录中独立的拖动排序。

每一块都是完整对话面：拥有自己的历史、输入框、草稿、模型控制和发送操作。两个对话默认均分可用空间，继续添加后最多形成四块。块与块之间有一条低干扰的可拖动分隔线：拖动只改变相邻两块，其他块继续占用剩余空间；双击分隔线或聚焦后按 Enter 会恢复全部均分，方向键可做细调。用户调整后的比例按当前对话组合保存在本机，刷新后仍会恢复。每个副块使用同源、隔离的 DSH 页面和独立会话选择键，因此在任一块切换、输入或刷新，都不会移动其他块的当前对话，也不会覆盖其他块的草稿。

当前页面只保留一份主目录和澜汐。副块不复制侧栏、详情栏、数字伙伴、用量、导出、浏览器入口和运行数据，让被压窄的会话优先保住正文与输入，而不是把整套桌面界面一起缩小。分隔线会按工作区总宽度计算每块的动态最小宽度；一块放大时只压缩其相邻块，并在四块和窄窗口下继续保住可输入区域，不产生整页横向滚动。拖动期间 iframe 暂停接收指针，避免鼠标被内部页面截走而出现卡顿或断拖。

分屏身份会在本机保存并随刷新恢复；已删除的对话、或后来成为主块的同一对话会自动从副块移除。每块有自己的轻量关闭键，关闭一块不会切换主对话，也不会中断其他块。插件通过 `sidebar.workspaces.sessionMenuAction` 和 `conversation.session.panes` 两个 slot 接入；Loader 技术 id 继续保留 `ui-multi-window`，避免热插拔配置和已有用户偏好失效。

## Model Experience

无。本包只协调页面呈现、会话导航和已有输入面，不新增提示词、工具、模型调用或隐藏 Agent 状态。

#### KV Cache effect

无。所有分屏仍通过 DSH 原生链路读写已有 Host Session。

## Known Limitations and Deferred Work

- 四块是为了保证 UI 可读性，不是 Session 或 Agent 并发上限。
- 技术包名继续保留 `multi-window` 以兼容已有配置；用户看到的产品能力统一称为“多对话分屏”。
- 热关闭插件会立即撤下分屏和入口；重新开启时仍可恢复之前保存的分屏选择。
