# 持续适配 UI

[English](README.md) | 中文

这是一个原生 Host + Client 插件，用于让 Xiaozhuang DSH 持续兼容上游预览阶段的破坏性变化。

设置入口和页面标题都是**持续适配**。原有按键继续支持用户主动更新。页面新增**自动更新 · 每 6 小时**胶囊，开启后立即开始监控并持久保存选择，此后每六小时检查一次官方分支。发现官方新提交时复用同一套外部更新事务；官方提交已经合入时不做任何操作。

快速链路会锁定官方提交，并通过一次真实试合并找出 Git 的实际冲突。独立候选工作树重复锁定合并，随后无论有无冲突都调用一次稳定版 DSH Agent。无冲突时最多用五分钟，只检查上游改动与本地插件直接重叠的文件或契约，确认兼容就不修改。存在冲突时不设进程超时，但任务严格限定在实际冲突文件及其直接编译依赖。两条路径都禁止广泛审查、全仓测试、构建、依赖安装、文档修改、重构、子代理和后台任务。候选版本随后只准备锁定依赖并执行一次生产构建。插件回归、独立全仓类型检查、Web 回放和切换前影子启动都明确退出产品更新链路。

构建通过后，工人等待所有实时对话空闲，停止旧运行时，创建一份写时复制数据快照，把源码切到候选版本，并确认重启后的 Host 和 Client 就绪。启动失败时，先恢复上一个 Git 提交和数据快照，再重新打开 DSH。一次生产构建失败最多触发一次窄范围修复；其他失败都不会替换当前产品。

冲突处理和构建期间，对话记录、附件、凭据和用户设置始终留在原 DSH Home。完成后会删除审查工作树、候选工作树、私有 Agent Home 和旧日志。源码版本由 Git 对象保存，保留策略最多留一份上一版写时复制数据快照，不会为每个版本复制一整套产品。

`/plugins/ui-adaptive-update/api` 下的 HTTP 入口只允许本机访问，负责主动开始、自动更新偏好、状态和空闲探测。操作状态与自动更新偏好都原子写入 DSH Home 之外，因此监控选择可以跨重启保留，新插件实例也能恢复被中断的切换，不依赖已被替换的旧进程。

## 模型体验

### 候选版本兼容请求

#### 模型看到什么

稳定版 Headless DSH Agent 会通过私有 CLI 设置覆盖层固定使用 `deepseek-official/deepseek-v4-flash-vision-exp`，不跟随用户当前选中的默认模型。无冲突候选只会收到确定性的重叠文件和直接受影响插件，并被要求在兼容时不修改代码。冲突候选只会收到 `conflictFiles` 和其直接受影响的插件边界，仅在必要时可修改直接编译依赖。两种任务都禁止提交、修改真实 DSH Home、广泛验证、修改文档、重构、启动子代理或后台任务，也不能停止当前产品。

#### Token 影响

每个已创建的候选版本都使用一次模型请求。无冲突请求最多运行五分钟；冲突请求不设进程超时，但保持更窄的文件范围。只有生产构建失败时才可能再使用一次有界请求；验证链路仍是一次依赖安装、每轮一次构建，且最多一次修复。

#### KV Cache 影响

适配运行在私有 DSH Home 和独立 Headless 会话中，不会向用户当前对话上下文追加或替换内容，因此不会让该对话的可复用前缀失效。

## 已知限制与暂缓工作

- **需要 Web Profile 运行**——六小时计时器只在 DSH Web 运行时工作。自动更新已开启时，下次启动会立即补一次检查，因此产品关闭期间发布的版本会在启动时被发现。
- **需要源码工作区**——更新器需要干净的 Git 工作区、可访问的官方 Git 远程、Node.js、pnpm，以及容纳一个候选工作树的临时空间；没有仓库元数据的打包安装不能使用这条路径。
- **写时复制数据快照**——不持续增长的回滚设计需要文件系统支持 clone 或 reflink 复制。不支持的文件系统会在切换源码前失败，不会转而复制完整 DSH Home。
