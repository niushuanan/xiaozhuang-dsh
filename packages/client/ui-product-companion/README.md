# @deepseek-ai/dsh-client-ui-product-companion

English | [中文](README.zh.md)

Native cross-page character and AI voice-input plugin for Xiaozhuang DSH. The default character is **Whale Girl**, with “Whale” carrying DeepSeek's whale-inspired visual identity. Users can rename her directly in the settings page bearing her current name; the settings navigation, accessible name, action menu, visibility switch, and page heading share one persisted preference while only the technical plugin id remains stable. The plugin contributes one additive entry to `shell.overlay`, so the character stays mounted while users switch conversations and product pages. It reads the existing session-list projection and selects a generated frame; a model call happens only after the user completes dictation with text refinement enabled:

- **Working** while any task is running.
- **Waiting** when a task needs approval, an answer, or plan review.
- **Success** for a short moment when running work settles.
- **Idle and sleep** while the workspace is quiet.

The companion now lives at the right edge directly above the real composer instead of roaming across unrelated product surfaces. Her visible silhouette touches the composer's top edge without covering its text. Quiet, working, waiting, and completion states remain prone. When sending a message or a layout reflow moves the composer, a redrawn 12-drawing close-camera doorway transition replaces the former crawl. The first portal drawing uses the same character width as the lounge pose; she raises her torso while the growing doorway progressively occludes her instead of cutting to a tiny full-body view. Coordinates switch only after the doorway fully hides her, then the drawings play in reverse at the new anchor. The root footprint, image plane, perceived character scale, and composer baseline stay fixed throughout. Standard and Large reuse the same proportional assets, and runtime movement never applies `scale()`. A `MutationObserver`/`ResizeObserver` measurement loop follows the real geometry. Ordinary layout changes are evaluated after a 120 ms anchor settle; conversation changes use a 360 ms trailing-edge settle window, and measurement noise below 6 px is ignored. A conversation change only suspends positioning and never supplies a target: a temporary bottom composer that returns to the same anchor does not open the doorway, while a genuinely different final anchor still does. Repeated geometry changes during one transition coalesce into the latest target. If the composer does not move, neither does the character. Single click, double click, and right click remain independently configurable. Their defaults focus the composer, start a new conversation in the current workspace, and open a compact menu directly below the character with one action: close the companion using her current custom name. The animation uses a 24 fps exposure sheet sampled by `requestAnimationFrame`: quiet acting is held on twos or threes and predecoded drawings swap on one permanently opaque image element.

One compact bubble shows the current live conversation title, phase, and observed elapsed time without pretending an indeterminate response has a percentage. The number below the character is the product-wide total of running or attention-blocked conversations. Clicking it expands prioritized task bubbles: user-blocked work first, then the current conversation and recently updated background work. Bubbles enter from the character upward with short staggered motion. Opening one navigates through the existing Session Runtime while keeping the whole task layer open, so the user can continue switching among concurrent work; clicking the number again, pressing Escape, or clicking outside collapses the bubbles back toward the character with the reverse stagger.

The waveform on the left now starts real voice input. Browser-native speech recognition inserts text at the current selection or caret in the real composer; clicking again or using the default `⌥ Space` shortcut ends dictation. Voice input can also be assigned to the single-click, double-click, or right-click companion action. Users may insert raw recognition, or select any connected DSH model and edit a prompt that defines cleanup, rewriting, or translation. The model request runs on the Host, so API keys never enter the browser. When refinement fails, raw recognition is inserted instead of discarding the user's words. Settings persist only the capability switch, model, instruction, shortcut, and aggregate dictation/character/time-saved totals; recordings and transcript history are never stored. Ordinary draft detection still retains only whether the composer is non-empty.

Preferences live in a dedicated **Digital companion** Settings section with custom naming, blue/black skin selection, Standard/Large size, gesture bindings, voice and rewriting controls, visibility, and the status-bubble switch. The same page also edits the active project's root `AGENTS.md` directly: it follows the current conversation's real working directory, creates the file on first save, supports `Cmd/Ctrl+S`, and refuses to overwrite a revision changed by an editor or another DSH window until the user reloads. This remains a companion-owned, hot-pluggable capability rather than a second plugin-inventory row or another top-level Settings section. Closing from the character persists locally and the same Settings switch restores it. The character steps out while a modal Settings surface is open and returns when that surface closes, so configuration controls stay clear. V8 uses 136 transparent runtime assets across four prone semantic loops and one fixed-scale 12-frame doorway transition. The clearly adult heroine keeps the accepted face, slender silhouette, DeepSeek whale jewelry, and glamorous non-explicit costume language. The selected skin's 68 assets are decoded up front. Deep Sea Blue is vivid cobalt and cyan; Night Black is a deterministic obsidian-and-silver palette with only small blue signals. Runtime pose transforms never rescale the character, and assets are checked for clear edges, camera consistency, matching blue/black silhouettes, stable semantic loops, portal-entry character width, and composer-baseline parity.

The Host half serves the 136 whitelisted immutable runtime PNG assets from `/plugins/ui-product-companion/assets/v8` and, within the same plugin lifecycle, loopback-only APIs for the model catalog, voice-text processing, and the fixed root `AGENTS.md`. The project-rules endpoint accepts only an absolute project directory and never accepts a caller-supplied filename; writes use a loaded-content revision and an atomic temporary-file replacement. The browser half owns state derivation, speech recognition, composer insertion, project selection, 24 fps exposure-sheet playback, composer geometry observation, and the two-phase doorway transition. Non-modal product panels such as Model Usage do not unmount it; only a true full-surface modal temporarily yields the canvas. Removing or disabling the `ui-product-companion` Loader row hot-unmounts the character, project editor, microphone entry, in-app shortcut, and Host APIs without altering sessions, the sidebar, the conversation UI, or another plugin. Enabling that row mounts the whole capability again without restarting the Web process.

## Model Experience

### Explicit voice-text refinement

#### What the model sees

Only after the user finishes a dictation with **Refine dictated text** enabled, the selected model receives a fixed system instruction requiring final text only, meaning preservation, and untrusted treatment of the transcript. One user message contains the transcript inside `<transcript>` framing; the user's editable cleanup, rewriting, or translation preference is appended to the system instruction. Ordinary companion animation, task bubbles, microphone recognition, and raw insertion make no model request.

#### Token effect

One bounded auxiliary request per refined dictation: at most 12,000 transcript characters and 4,000 preference characters enter the request, and output is capped at 2,048 tokens. No tool schema or conversation history is included. If every automatic route fails, the browser inserts the raw recognition instead of sending another request.

#### KV Cache effect

Each dictation is an independent one-shot request with no conversation history. It neither contaminates the active conversation's KV cache nor benefits from that cache.

## Known Limitations and Deferred Work

- The companion intentionally has no second chat box, feeding loop, currency, growth system, or minigame. Those concepts duplicate the main product workflow and add ongoing attention cost.
- A session that completed before this plugin mounted does not replay the success frame; only live running-to-settled transitions celebrate.
- Elapsed time is an honest browser-observed duration. Reloading the page in the middle of a task restarts that local counter instead of inventing an earlier start time.
- The companion appears only where the real composer exists; Settings dialogs and pages without a composer intentionally leave the surface clear.
- Project instructions are scoped to the current conversation's project. A conversation without a recorded working directory shows guidance instead of inventing a global target.
- This version uses the browser-provided speech-recognition interface. First use needs microphone permission, and offline behavior or supported languages depend on the browser and operating system. The shortcut is in-app while the DSH window is focused; a system-wide shortcut still requires a future native macOS helper.
