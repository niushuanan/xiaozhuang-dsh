# @deepseek-ai/dsh-client-ui-outline

[English](README.md) | 中文

对话大纲插件。`OutlineRail` 填充常驻会话外壳的增量槽位 `conversation.session.outline`：当对话覆盖三轮及以上时，在对话列左缘渲染一条窄刻度轨。

每个刻度对应一轮，全部从会话套件的标准 chat 快照（`chat.order` + `chat.nodes`）推导：轮次边界跟随每条可见行的 `location.turn`——提问行不 gate 推导，因为编码视图不渲染提问行，且首页历史可能覆盖若干轮而它们的提问落在窗口之外。`user`/`steering` 行把截断文本贡献给下一轮的预览；预览在有提问时显示问题，无论如何都显示该轮最终一条助手消息的开头文本，刻度宽度按该轮助手文本总长分档，使轨道呈现对话形态。滚动侦测跟随对话滚动容器（同列下的 `[data-conversation-scroll]`）的滚动事件与聊天流的尺寸变化，标出阅读线以上最后一轮的位置，当前刻度加深。点击刻度把该轮已渲染的行（`data-chat-anchor-key`）平滑滚动到视口顶部，走聊天视图既有的滚动记账。悬停刻度在锚定于刻度的穿透卡片中预览该轮。

历史分页按消息数限定，因此工具量巨大的尾页可能只有少数几轮。只要还有更早历史，轨道就通过会话对象面的 `loadOlder` 逐页载入，直到历史起点。分页只在会话打开后开始；重连或重同步已经重建窗口时，过期分页响应会被忽略，轨道从新窗口继续加载，不会把旧页误判为历史断层。固定高度的轨道把已载入轮次均匀分布在对话列范围内，密集对话会缩短刻度，而不是裁掉后续轮次。

座位本身由会话骨架持有的零宽穿透覆盖层，在内嵌窗格、分屏布局与多窗格分组下隐藏；轨道只对自身重新启用指针事件。目标槽位由另一插件声明，因此 `apply` 使用 `slots.inject()` 按声明生命周期注册，并在声明恢复后重新注册。

## Model Experience

无：大纲是浏览器界面元素，不触及模型请求。

#### KV Cache effect

无；本包既不组装也不发送 provider 请求。

## Known Limitations and Deferred Work

- **轨道逐步补齐**——尾页打开后会串行载入更早分页；长对话的最早刻度会随分页逐步出现，不会阻塞对话视图。
- **进行中轮次的摘要补齐较晚**——轮次预览在存在助手消息后显示回答文本；流式进行中的轮次在消息定稿或下一轮开始前只显示问题。
- **物理密度仍有下限**——刻度最短缩到两个 CSS 像素；当轮次数超过对话列在该下限下的可表达范围时，无法再为每一轮提供较大的指针热区。
