# @deepseek-ai/dsh-client-ui-multi-window

[English](README.md) | 中文

DSH 原生多窗口插件。启用后，会话行的 `…` 菜单会在“重命名”“分叉会话”“归档会话”之后增加“另开窗口”。点击后打开一个完整的 DSH 附属窗口，并直接定位到所选会话；主窗口和每个附属窗口都可以独立切换对话、输入和发送消息。

插件把“当前会话”按窗口身份分别持久化。主窗口仍使用原有 `dsh.sessions.current`，附属窗口使用自己的稳定窗口 id，因此第二个窗口切换会话不会改变主窗口高亮，任一窗口刷新也不会把其他窗口带走。附属窗口每次切换会话时会同步自身 URL 和标题，重载后仍回到自己的最后位置。

同源窗口通过 2 秒心跳的本地租约统计存活状态，主窗口在内最多同时 4 个 DSH 窗口。点击动作会先占用一个名额再打开窗口，浏览器拦截弹窗时立即归还；正常关闭使用 `pagehide` 释放，异常关闭最迟在 7 秒后过期。窗口尺寸根据可用屏幕计算并轻微错开，不修改主窗口尺寸，也不把四个会话硬塞进同一页面。

数字伙伴属于用户的主工作位。附属窗口仍可进入数字伙伴设置，但不注册第二份跨页面角色 overlay，因此不论打开两个还是四个窗口，只有主窗口显示“鲸少女”。

插件通过 `sidebar.workspaces.sessionMenuAction` slot 注入菜单行，并由 Loader 行 `ui-multi-window` 控制。关闭插件时菜单能力与窗口租约协调器即时卸载；已经打开的窗口不会被强制关闭，避免中断其中正在生成或尚未发送的内容。

## 模型体验

无，因为本包只协调浏览器窗口、页面导航和菜单呈现，不注册 prompt、工具、消息或模型请求。

#### KV Cache effect

无；多窗口共享 Host 中已有的会话事实，但每个窗口只是同一业务数据的独立 UI 观察与输入面。

## 已知限制与暂缓事项

- 新窗口仍受浏览器或桌面壳的弹窗策略约束；必须由用户点击“另开窗口”触发，不能在后台自动弹出。
- 4 个窗口是当前产品上限，不是底层会话或 Agent 的并发限制。
- 热关闭插件不会关闭已有附属窗口；它只撤下新增入口并停止窗口数量协调。
