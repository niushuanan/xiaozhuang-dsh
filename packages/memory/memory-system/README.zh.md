# `@deepseek-ai/dsh-memory-system`

[English](README.md) | 中文

DSH 原生的双文档全局记忆体系。它只在 `<DSH_HOME>/memory` 下维护固定文件：`user.md` 保存用户明确要求记住的内容，`ai.md` 保存 Agent 从对话中主动维护的经验。两份文档都在设置页可见、可直接编辑，保存时校验内容修订值，保留历史版本，并提供一步恢复。

用户点击**记忆**时，系统不会把选中文字原样粘进 `user.md`。Host 会先移除常见凭据形式，再把完整当前文档和有界来源上下文交给记忆模型，要求输出带适用范围和来源信息的完整替换文档。文档确实变化时才原子写入并提供立即撤销；如果现有记忆已经覆盖这份经验，操作正常完成，但不会制造重复版本和无意义的撤销状态。除手动编辑和用户明确触发的记忆外，后台不会改写 `user.md`。

每天本地时间 12 点后，插件扫描上次成功游标之后的用户与助手对话；首次运行只从本地当天零点开始，不会回放用户的全部历史。只要已经知道可用模型路由，就让模型把 `ai.md` 当作一份持续维护的活文档：新增长期有用的经验、合并重复内容、更新已经变化的结论，并删除不再值得保留的记录。对话很多时会拆成多次有界模型调用，但不会丢弃任何对话证据；所有批次成功后才推进游标。它不会追加每日摘要，也不设置生硬的字数或条数上限。DSH 在 12 点没有运行时，会在下次获得可用模型路由后补跑。

普通请求第一次调用模型前，插件会按当前问题与项目路径匹配由 Markdown 分隔线划分的记忆块。最多注入四块、4,000 字符，并始终把用户主动记忆排在 AI 主动记忆之前。没有相关命中就完全不注入。召回内容紧挨本轮请求之前放置，并包在明确的不可信数据边界内；它可能过时，不能覆盖随后出现的本轮请求、项目规则或当前证据。

## Model Experience

### 按相关性召回记忆

#### What the model sees

请求第一步存在相关命中时，模型会在当前用户请求之前看到一条 `relevant-memory` 插件快照，其中只有少量匹配的 Markdown 记忆块。用户主动记忆排在 AI 主动记忆之前；明确的 `<memory_data>` 边界把全部内容标为不可信、可选且可能过时的参考，优先级低于随后出现的当前请求和当前证据。

#### Token effect

没有命中时为零。命中时只在第一步增加最多四块、4,000 字符；普通 Agent 请求永远不会载入完整记忆文档。

#### KV Cache effect

召回只在稳定的较早历史之后、当前请求之前插入一条相关插件消息。后续请求可以选择不同记忆块，不改写此前 Session 事件。

### 记忆维护模型调用

#### What the model sees

独立的记忆调用会看到目标 `user.md` 或 `ai.md` 文档全文，以及一份用户主动选择的有界来源，或成功每日游标之后的有界用户与助手对话变化。提示要求输出一份完整替换文档，不是只增不减的摘要，并把全部来源当作不可信数据。

#### Token effect

主动记忆会使用一次独立模型调用。每日维护只有存在新对话材料时才运行，并使用一次或多次有界调用，让成功游标窗口内的全部对话都参与维护。

#### KV Cache effect

维护调用与当前对话请求分离，不改写当前对话缓存。文档变化只可能影响以后独立命中相关记忆的请求。

## Known Limitations and Deferred Work

- 每日维护需要从一个活跃 DSH Agent 得到模型路由；当前和历史都没有成功路由时会等待，不猜测提供方。
- 12 点计划使用运行机器的本地时区；电脑休眠或进程停止时，会在重启并获得路由后补跑。
- 设置页有意只提供逐次恢复上一个版本；更早文件继续保留在 `<DSH_HOME>/memory/history`，不额外增加历史管理页面。
