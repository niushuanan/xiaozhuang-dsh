# Agent Note: Add a native state-driven product companion

Status: implemented

English | [中文](2026-08-24-native-product-companion.zh.md)

## Problem

Xiaozhuang DSH has several useful native plugins, but the product has no continuous character that survives page changes or turns background Agent state into a lightweight ambient signal. Existing DSH pet plugins prove that idle, working, waiting, completed, error, dragging, and sleep states are understandable. Their broader feeding, currency, growth, minigame, multi-pet, and second-chat systems would duplicate the main DSH workflow and add a large new state domain.

A companion implemented inside a particular sidebar, conversation, or Settings component would disappear when that owner unmounts. A pure decorative animation would also consume screen space without helping the user notice pending approvals or ongoing background work.

## Decision

Add `@deepseek-ai/dsh-client-ui-product-companion` as a dual-face native plugin. Its browser half contributes one root-scoped entry to the additive `shell.overlay` slot. The companion therefore remains mounted above all app columns and pages without replacing any layout owner. It consumes the existing session-list projection and deterministically derives working, waiting, short success, idle, and sleep states. It makes no model request and owns no session truth.

The Host half exposes only 124 whitelisted immutable PNG frames from `/v8/`. Built-in ImageGen preserves one clearly adult 29-year-old identity, the accepted face, a tall slender frame, natural proportions, DeepSeek whale jewelry, and a glamorous non-explicit costume language. Four accepted prone boards provide 20 composer-lounge, 12 prone-focus, 12 prone-waiting, and 12 prone-success drawings; the accepted six-drawing doorway board replaces the retired human crawl. Semantic states share one locked camera, body scale, and composer contact baseline. The doorway is normalized to the same 295 px longest body axis and 343 px bottom baseline before entering V8. The reproducible build keeps complete grid cells, chroma-keys magenta, removes detached residue, and contain-fits accepted compositions to a transparent 384 × 384 canvas without stretching anatomy. The same cleaned frames generate a deterministic Night Black palette. Frame tests reject non-transparent edges, mismatched blue/black outlines, unstable semantic loops, or a portal frame that changes optical body length or baseline. The browser decodes all 62 authored frames for the selected skin before playback.

The visible surface stays borderless and offers Standard and Large optical sizes. Runtime CSS adds no drop shadow to the generated silhouette. The character is permanently anchored directly above the measured composer's right edge; each size has an asset-calibrated bottom inset so the visible body touches the border without covering composer text. Every semantic state remains prone. When sending or layout reflow changes composer geometry, `MutationObserver`, optional `ResizeObserver`, scroll observation, and a short `requestAnimationFrame` measurement window update the target anchor. The character stands and plays the six doorway drawings at the old anchor, switches the root coordinate only on the closed-door frame, then reverses the same drawings at the latest target and returns to the appropriate prone loop. Geometry changes that arrive during a transition coalesce to the newest target. The root footprint, image plane, optical body length, and bottom baseline stay constant; CSS applies no travel transition or scale. If geometry does not change, position does not change. User drag, free placement, and idle side switching remain absent. Single click, double click, and right click have independent persisted bindings. Defaults reuse the shell's existing focus-composer and current-workspace new-session actions plus one product `Menu` with new-session, focus, and close entries. A 240 ms single-click gate prevents the first click from firing when a double click follows. All acting is sampled from the 24 fps exposure sheet by `requestAnimationFrame`, and predecoded drawings swap on one permanently opaque image plane.

GitHub research changed both the status and playback contracts. OpenAI Codex maps named tracks to semantic running, waiting, review, and failed notifications, with explicit sprite indices, frame durations, loop points, and fallback. VS Code Pets changes the animated source only when the state changes, while a separate state machine advances position and behavior. Both reinforce that persistent product state and continuous movement must not be implemented by repeatedly replacing unrelated full-body poses. DSH adopts only the parts that solve its core task: stable semantic poses, compositor-driven movement, a compact live phase plus browser-observed elapsed time, no fake percentage, no prompt or generated-text read, and no extra Agent call.

The root store is shared by `shell.overlay` and a dedicated `settings.section`. Settings owns blue/black skin selection, Standard/Large size, the three shortcut bindings, companion visibility, and status-bubble visibility. The visibility switch is the recovery path after close. The companion observes only authoritative session phase and a boolean indicating whether the real composer is non-empty; it never retains message text. Its task count expands the existing session projection into independent staggered bubbles. Selecting a bubble changes the current session without closing the task layer, while the count toggle, Escape, and outside click own an animated collapse. It intentionally steps out while a modal Settings surface is present and returns after the dialog closes. Old persisted records fall back to visible, Large, focus/new-session/menu bindings. The design intentionally excludes free or vertical placement, persisted manual positioning, feeding, growth, currency, games, a status card, and a second chat.

## Alternatives considered

**Place it inside the sidebar.** This would make the default pose feel attached to the directory, but the companion would disappear in collapsed, Settings, and non-sidebar layouts. The shell overlay preserves the visual placement while keeping the character cross-page.

**Add an independent pet backend and model conversation.** This enables more personality, but creates another prompt, history, cost, and failure path. The existing session projection already contains the useful product signals.

**Generate every Night Black frame independently.** This offers more local pose variation, but repeatedly drifted the face, anatomy, and cell boundaries and made blue/black frame timing impossible to align. The selected pipeline applies a constrained palette transform only to blue-dominant clothing regions after background cleanup; skin, whites, alpha, and cyan highlights stay intact.

## Consequences

The companion can be enabled or removed as one Loader plugin row. It alerts the user to waiting tasks, mirrors active work with honest observed time, celebrates live completion, and remains visually attached to the one surface where the user and Agent exchange work. Runtime ships 124 compressed PNG frames; the preserved character reference and five accepted source sheets remain auditable development material and are excluded from the package. Future state changes must continue to derive from existing authoritative projections rather than creating a second task-state machine, reintroducing crawl-based root movement, or making pointer movement drive the character.
