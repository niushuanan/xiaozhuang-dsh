# Agent Note：新增原生状态驱动产品伙伴

状态：已实现

[English](2026-08-24-native-product-companion.md) | 中文

## 问题

Xiaozhuang DSH 已经包含多个实用原生插件，但产品里还没有一个能跨页面持续存在的角色，也缺少一种把后台 Agent 状态变成轻量环境提示的方式。现有 DSH 宠物插件已经证明，空闲、工作、等待、完成、错误、拖动和睡眠状态容易理解；但它们更完整的喂养、货币、成长、小游戏、多宠物和第二聊天系统会重复 DSH 主流程，并新增很大的状态领域。

如果把伙伴放在某个目录、对话或设置组件内部，拥有者卸载时它就会消失。纯装饰动画也只会占用空间，无法帮助用户注意待批准任务或后台工作。

## 决定

新增双端原生插件 `@deepseek-ai/dsh-client-ui-product-companion`。浏览器端向可叠加的 `shell.overlay` 插槽贡献一个根作用域入口，因此伙伴可以持续挂载在所有应用栏位与页面之上，不替换任何布局拥有者。它消费现有会话列表投影，以确定性方式派生工作、等待、短暂完成、空闲和休息状态；不发起模型请求，也不保存第二份会话真相。

Host 端现在只提供 60 张白名单内的不可变 PNG。ImageGen 生成同一个明确为 27 岁的成年日漫女性身份，以及目录、页头、输入区、任务生命周期和安静／休息五张深海蓝六帧源图。构建过程按照原生 3 × 2 网格逐格切割，清理生成图中的棋盘背景，统一到 384 × 384 透明画布，再从同一组轮廓确定性生成夜航黑配色，因此两套皮肤的身份和时序完全一致。浏览器只预加载当前皮肤。

可见界面保持小巧、无卡片边框。角色本身就是直接交互面：点击只在当前位置回应，不再改变停靠点；拖动是唯一直接移动方式。拖到目录、页头或输入框边缘附近会自动吸附，同时允许自由放置。停靠点来自真实页面布局测量，不保存易失效的死坐标。每个停靠点使用独立的六帧动作；鼠标靠近会跟随视线，安静时只在原地做偶发动作，运行任务会优先靠近输入区，任务完成会播放一次短任务回应。

GitHub 调研改变了状态契约。OpenAI Codex 把宠物动画映射到运行、等待、审查和失败等语义通知；它的公开源码和问题记录也证明，活跃动画必须跟随权威任务状态，不能依靠固定倒计时擅自结束。`SHIN620265/claude-pet` 证明伙伴可以展示思考、等待、后台运行、完成和中断状态，同时把隐私控制放到独立设置中。OpenPet 与 CoPet 则把鼠标直接互动和设置中心分离，并提供事件反应、自动活动、减少动画和消息展示选择。DSH 只采用真正解决主任务的部分：紧凑的实时阶段与浏览器实际观察到的用时，不显示假百分比，不读取提示词或生成正文，也不新增 Agent 调用。

根作用域 store 同时交给 `shell.overlay` 和独立 `settings.section` 使用。因此角色点击路径只负责原地回应，而设置页统一管理蓝黑皮肤、状态提示、自动跟随任务和恢复位置。旧持久化记录会回退到新功能默认开启的状态。设计明确排除喂养、成长、货币、游戏、状态卡片和第二聊天框。

## 考虑过的替代方案

**放进目录内部。** 这能让默认姿势更像趴在目录上，但目录收起、进入设置或使用其他布局时伙伴会消失。Shell overlay 在保持视觉位置的同时实现真正跨页面。

**增加独立宠物后端和模型对话。** 这可以提供更多性格，但也会产生另一套提示词、历史、成本和失败路径。现有会话投影已经包含真正有用的产品信号。

**分别生成每一张夜航黑帧。** 这能获得更多局部变化，但会不断漂移面部、肢体和单元格边界，也无法让蓝黑两套帧严格同步。最终流程只在背景清理后对蓝色主导的服装区域做受控调色，肤色、白色区域、透明度和青色高光保持不变。

## 影响

伙伴可以作为一条 Loader 插件配置独立启用或移除。它会提示等待任务、用真实观察时间映射运行工作、庆祝实时完成、跨页面保持存在，并在不拥有产品区域的前提下与当前区域产生关联。运行帧约增加 7 MB 压缩 PNG；保留的角色母版与五张源图约 12 MB，用于审计生成来源但不会随包发布。后续新增状态仍必须从已有权威投影派生，不能再创建第二套任务状态机，也不应重新打开伙伴设置卡片。
