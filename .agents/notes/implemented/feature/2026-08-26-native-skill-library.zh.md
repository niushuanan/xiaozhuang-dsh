# Agent Note：原生 Skill 能力库与自适应导入

状态：已实现

[English](2026-08-26-native-skill-library.md) | 中文

## 问题

Skill 过去只在调用时可见。用户无法集中浏览个人、项目、运行时、自定义和内置来源已经提供的能力，也无法在不打开其他工具的情况下查看一个多文件 Skill，更不能把任意文件、文件夹、压缩包或仓库安全地整理成个人 Skill。

## 决策

Web bundle 把 `@deepseek-ai/dsh-client-ui-skill-manager` 作为标题为 **Skill 管理**的原生设置分区。它解析当前 Session 的 cwd、实时 Agent、预设和作用域 Skill 注册表，与输入框使用同一来源，而不是新建第二套目录或只读取全局兜底。每个最终生效的 Skill 行都展示可写徽章，并统一复用产品既有的 `IconSkillOutline16`。首屏是限宽单列目录，行内还展示 AI 判定的 frontmatter 分类标签和截断介绍（见 [Skill 分类标签来自 frontmatter 字段，客户端不做推断](2026-08-27-skill-category-tag.zh.md)）；点开一项后，目录会切换成专注阅读区，把默认紧凑且可展开的人性化说明放在左侧文件树与正常宽度的选中文件上方，并用一个返回入口恢复目录。可视化 Markdown 预览会省略开头的 YAML frontmatter，但不修改源文件。

一个黑色的**导入 Skill**菜单把文件、浏览器选择的文件夹与普通 GitHub 仓库地址作为并列来源。选择文件或文件夹会立即打开浏览器选择器，选择 GitHub 才展开行内地址输入框；ZIP 压缩包走文件入口。Host 把来源作为不可信数据暂存，拒绝不安全路径和符号链接，不向模型提供常见密钥文件，并限制文件数量和字节数。GitHub 来源只做单分支浅克隆；ZIP 在解压前校验每个条目。

归一始终在用户 Session 之外调用无工具的 `deepseek-official/deepseek-v4-flash-vision-exp`。模型只能提出一份经过校验的 `SKILL.md`，以及指向已暂存资源的映射。同名冲突只会增加一次窄范围请求，并只带上现有 Skill 的直接定义。Host 校验结果后把候选原子切换到 `$DSH_HOME/skills`；替换失败会恢复旧的个人 Skill。项目、运行时、自定义和内置来源永远不会被写入。

## 验证

`apps/web/tests/skill-manager.e2e.ts` 使用一项隔离的个人 Skill 启动正式 Web 组合。它的无密钥快照锁定目录、条件式 GitHub 表单、专注详情阅读区、隐藏 frontmatter 的可视化预览，以及宽度超过 300 像素且宽于文件树的正文区。

## 考虑过的替代方案

**另建一套 Skill 数据库。** 不采用，因为 Provider 优先级、热刷新和调用已经属于 `ctx.skills`；第二套存储迟早会与 Agent 真正能调用的能力不一致。

**用操作系统编辑器打开 Skill 文件。** 不采用，因为用户任务是发现和理解；同页查看让目录、说明和文件内容保持在一个可预期的界面。

**让 Skill 目录、文件树和正文永久保持三列。** 不采用，因为设置内容栏无法同时给三列足够的阅读宽度。目录到阅读区的切换仍然只占一个页面和一个返回动作，同时把详情空间留给文件树与正文。

**把上传内容直接复制进个人目录。** 不采用，因为任意材料可能不是合法 Skill，也可能包含路径穿越、密钥或与现有正常 Skill 冲突。暂存、有界归一、校验和原子替换让导入失败仍可恢复。

**使用当前对话模型。** 不采用，因为导入属于产品自有的后台 AI 功能。固定低成本路由后，它不会被用户为工作或聊天选择的模型改变。

## 结果

用户现在可以先快速浏览自己有哪些 Skill，再阅读其中一个，而不会让第三列把正文挤窄。外部材料通过统一导入控件变成个人 Skill，既有来源继续保持权威和只读。从目录进入阅读区需要一个明确的返回动作。首版只展示同名 Skill 中最终胜出的 Provider，并同步完成导入；它没有增加第二套 Skill 协议、后台任务历史或导入内容的执行权限。
