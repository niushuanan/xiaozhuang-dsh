# Agent Note: 设置目录长按排序

Status: implemented

[English](2026-08-25-settings-navigation-reorder.md) | 中文

## Problem

设置外壳按各 `settings.section` 注册项的 `order` 值排列全部分区。这个顺序适合作为产品默认值，但经常访问某些插件页面的用户无法把它们放在一起。单独增加一张定制页面或持续编辑模式，则会给原本只需直接操作的导航引入额外控件和状态。

较短的设置目录还会在轨道下方留下大量空白。空白区中的指针坐标仍然必须落到真实的首个或末尾插入点；如果把整块面板高度当成潜在位置，就会产生不可见或无法再次命中的顺序槽。

## Decision

现有 `ui-settings-general` 原生插件负责目录排序，因为它已经持有 `sidebar.settings` 条目、投影全部分区行并绘制左侧轨道。该条目声明一个根级 store，只保存排好序的分区 id。渲染时把这份偏好与实时分区账本对齐：仍存在的已保存 id 排在前面，新注册的 id 按插件原有顺序追加，不存在的 id 直接忽略。

主指针按住一秒后开始拖动。达到长按阈值前发生移动会取消手势，因此普通单击维持原有行为。拖动期间，外壳把指针纵坐标与除当前项之外的每个真实目录中心比较；坐标高于所有中心时对应索引零，低于所有中心时对应最后一项之后。这个限制让短目录下方的整片空白都能把项目送到最后一个真实位置，同时不会制造空白位置。

轨道只在目标边界绘制一条两像素插入线，并降低当前项透明度。指针捕获保证光标离开目录行后手势仍连续。松手会写入全部可见 id 的顺序，同时抑制同一指针序列产生的单击；产品不增加编辑模式、排序按钮、确认步骤或单独设置页。

## Alternatives considered

**单独的导航定制页或编辑开关。** 未采用，因为它会为一个手势即可完成的任务增加模式、控件、文案和第二条保存路径。

**HTML 原生拖放。** 未采用，因为浏览器原生反馈和触摸行为并不一致；指针事件可以统一鼠标与触摸几何，并让产品自己控制插入线。

**把替换后的 `order` 值写回各功能注册项。** 未采用，因为外壳交互不应修改插件所有的注册信息。由外壳持有一份 id 列表并覆盖实时账本顺序，不需要改变功能包或注册契约。

## Consequences

用户可以排列当前全部可见设置分区，包括第三方插件页面；顺序会跨设置面板重新挂载和浏览器刷新保留。动态移除或新增插件仍然安全，因为偏好会与账本对齐，而不会被当作一份完整注册表。该偏好只是浏览器本地查看状态，不修改 `settings.yaml`、插件配置、模型输入或 KV Cache。

组件测试固定一秒阈值、唯一插入标记、向两个真实边界的限制，以及重新挂载后的持久化。组装浏览器继续负责验证指针捕获、插入线位置和普通点击导航不变。
