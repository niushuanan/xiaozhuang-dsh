# Agent Note: 原生命令、插件与技能菜单

Status: implemented

[English](2026-08-23-composer-add-menu.md) | 中文

## 问题

输入框加号菜单已经展示图片、工作区引用和由斜杠来源提供的 Skill，但 Host 官方命令位于 `ui-commands` 按会话维护的目录中，不属于斜杠 lexicon。因此同一条命令在输入 `/` 后可见，点击更适合发现能力的加号时却消失。该菜单也仍是 Profile 外置包，但它已经是产品常驻界面。

## 决策

`ui-conversation` 声明纯数据 `ComposerCommandCatalog` 合同，并在既有 `conversation.input.add` owner props 中新增 `commandItems`。`ui-commands` 直接使用现有的按会话 `CommandDirectory` 实现该可选服务；成功刷新后发布稳定可观察的官方 `{ name, description }` 投影，命令、预设和连接失效都更新同一来源。没有新增第二套 RPC 或目录。

`InputBar` 订阅官方目录，并继续把斜杠来源条目作为 `slashItems`。同名时官方命令优先。共享的 `onInsertSlashItem` 同时接受两类条目，只在当前文本选区插入 `/name `，绝不直接调度命令。

仓库内的原生 `@deepseek-ai/dsh-composer-add-menu` 包占用既有单一添加 slot。第一组复用原生图片接收和工作区引用回调。**命令、插件与技能**分组先用现有插件图标展示官方命令，再用现有 `IconSkillOutline16` 展示 Skill。选中后关闭菜单并调用 owner 插入回调；点击外部、Escape、禁用状态与焦点恢复继续沿用既有行为。移除占用项后仍会显示原始命令启动 fallback。

## 考虑过的替代方案

**把斜杠弹层复制到添加插件。**否决，因为第二套命令拉取、缓存和失效链路会与 `/` 真实展示的内容偏离。

**再放一层“运行命令”入口。**否决，因为用户需要在加号中发现命令，多一层目录只会再次隐藏同一份信息。

**把官方命令当成 Skill lexicon 条目。**否决，因为 lexicon 表达引用和 Skill，而官方命令的可用性和描述是归属于当前会话和 Agent 的 Host 事实。

**继续保留 Profile 外置包。**否决，因为核心组合界面必须随产品源码一起构建、类型检查、导出和适配，不能依赖某台电脑的 Profile。

## 后果

点击加号后，用户现在会先看到当前会话可用的同一批官方命令名称与描述，再看到插件和 Skill，同时保留图片和工作区操作。选中结果在用户发送前仍是可编辑文本。目录实时失效、同名优先级确定，菜单不新增业务协议或持久状态。

## 验证

定向目录和对话测试覆盖首次发布、命令／预设／重置实时失效、官方同名优先、按选区插入和可选服务 fallback。原生菜单组件测试会打开可见加号菜单，检查精确产品标题下官方命令位于 Skill 之前，并确认选中命令只调用插入回调、不执行。组装 Web 冒烟检查仓库原生包已进入对话图。
