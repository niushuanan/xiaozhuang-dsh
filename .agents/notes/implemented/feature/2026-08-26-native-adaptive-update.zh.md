# Agent Note: 原生自适应更新

Status: implemented

[English](2026-08-26-native-adaptive-update.md) | 中文

## 问题

DSH 仍是早期预览产品，上游变化可能同时让包结构、Client 合同、Profile 组装、持久化假设和本地插件失效。直接把这些变化应用到正在运行的工作区，会让产品在冲突尚未理解或修复时就无法使用。

## 决策

Web Profile 内置一个名为 `@deepseek-ai/dsh-client-ui-adaptive-update` 的原生 Host + Client 插件。设置入口和页面标题都是**自适应更新**。用户开始操作后，系统锁定一个官方提交，并把所有长时间工作交给能够独立存活于当前 DSH 进程的外部工人。

外部工人在可丢弃审查工作树中执行一次真实合并。稳定版 DSH Headless Agent 审查这棵精确的工作树，但不修改它。然后工人删除审查树，在独立候选工作树重复同一个锁定合并，再让稳定 Agent 解决和适配候选版本，不提交，也不修改真实 DSH Home。

候选版本必须没有未解决合并项，并且通过锁定依赖安装、更新器回归、Host 和 Client 类型检查、生产构建、Web 回放和影子 Host + Client 启动。这些阶段不修改当前工作区和用户数据。

## 切换事务

验证通过后，外部工人提交候选版本，等待所有根 Agent 空闲，停止当前运行时，创建一份 DSH Home 写时复制快照，并把干净工作区前进到候选提交。候选版本必须让 Host 页面和 Client 资源同时可访问。启动失败时，工人会在重新启动旧运行时前恢复上一个 Git 提交和数据快照。

操作状态以原子方式持久化到 DSH Home 之外的插件自有同级目录。后续插件实例可恢复被中断的应用阶段：已就绪的候选版本完成操作，其他状态恢复上一个提交和快照。

## 保留与隐私

审查和验证只把稳定 Agent 必需的配置文件复制到私有影子 Home。会话、附件、工作区和其他用户数据始终留在真实 Home。源码历史由 Git 对象保留；成功清理会删除审查、候选、影子和日志产物，最多留一份上一版写时复制数据快照。

## 考虑过的替代方案

**在当前工作区合并上游。**这无法在修复冲突、依赖变化和启动失败时保持产品可用，因此一次失败编辑就可能让整个 DSH 进程崩溃。

**每当上游移动时自动更新。**后台代码替换可能中断正在进行的工作，也会在没有用户意图时做语义兼容决定。当前操作由用户主动开始，并在任何切换之前用足够长时间完成审查。

**每个版本保留一个完整产品目录。**完整复制会让保留空间每个版本增加数百 MB。Git 历史、可丢弃工作树和一份写时复制数据快照可以提供回滚，不需要永久版本目录。

**在运行进程内修补 Loader 状态。**包、Host、Client 和持久化变化没有同一个可逆的进程内边界。外部候选区和重启事务把不确定工作留在被保护的进程之外。

## 后果

用户可以在审查、适配和验证期间继续使用旧版本，活跃对话会延后短暂切换。对话和附件存储在更新过程中保持权威。该设计会使用一个临时候选工作区、两次独立模型请求和一份保留的写时复制快照；它也要求干净 Git 工作区和支持 clone 或 reflink 复制的文件系统。
