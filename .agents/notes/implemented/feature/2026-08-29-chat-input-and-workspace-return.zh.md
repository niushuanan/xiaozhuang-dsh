# Agent Note: 能力受限的聊天输入与工作区返回

Status: implemented

[English](2026-08-29-chat-input-and-workspace-return.md) | 中文

## 问题

原生聊天需要图片、文本文件和当前公开信息等常见问答输入，同时不能继承工作区或本地执行权限。工作输入框还需要继续使用既有的文件与文件夹引用路径；从聊天返回 Agentic Coding 时，也需要进入可预测的工作区，而不是无关的最近选择。

## 决定

聊天与工作会话渲染同一个输入框添加位。它的菜单接受受支持的图片，以及用户主动选择的文本、Markdown、表格、配置、日志与源代码文件。文本文件会进入可编辑草稿；图片接收继续沿用既有的模型与附件检查。聊天不展示工作区引用、命令、Skill、访问模式或项目运行上下文。

随产品提供的 `chat` 预设只挂载公开 Web 搜索与读取 consumer。输入框会在添加按钮旁显示紧凑的状态图标，让这项能力保持可见；模型会自行判断问题是否需要当前信息或来源支撑。该状态不是逐条消息切换的模式，也不代表本地浏览器或电脑控制。

工作会话通过对话添加位 owner 传递实时引用触发器。**文件与文件夹**会在当前光标位置打开既有工作区引用选择器，不再展示永久禁用的条目。

未显式指定工作区就启动 Agentic Coding 时，如果当前工作会话已有工作区，则继续使用它；否则选择工作区浏览器可见顺序中的第一个工作区。启动恢复仍可使用最近记录，因为它是在恢复既有导航，而不是响应一次明确的模式切换。

独立纯聊天导出只控制专用聊天启动行，并从当前仓库路径携带聊天启动器、输入框添加菜单、共享对话界面和随产品提供的聊天预设。这样独立安装包会跟随真实产品闭包，不再导出已经移除的旧预设路径。

## 考虑过的替代方案

**让聊天保持纯文本且离线。** 这能保留最窄的能力集合，但会阻断需要附件或当前公开信息的常见任务，而这些任务都不要求项目权限。

**在聊天中开放工作命令、Skill 或工作区引用。** 这会让两种模式看起来相似，却抹掉让聊天安全且易理解的权限区别。

**增加一个逐条消息改变行为的联网开关。** 第二种状态要求用户预判问题是否需要搜索。始终可用的可见状态既能传达能力，也不会再增加一个需要管理的模式。

**离开聊天时恢复最近活跃的工作区。** 最近记录可能选中当前浏览上下文下方很远的文件夹。第一个可见工作区是确定的，并与用户当前看到的导航顺序一致。

## 后果

聊天用户可以上传普通文件与图片，并获得联网支撑的回答，同时聊天模式仍不能检查工作区或操作电脑。工作用户可以再次从输入框打开文件与文件夹。切换到 Agentic Coding 时会落到当前工作上下文或第一个可见工作区，因此过期的最近文件夹不会劫持这次切换。

定向组件与服务测试覆盖聊天菜单、联网能力标记、实时引用触发器与工作区 fallback。组装后的真实产品路径验证实际文件接收、公开 Web 搜索工具轮次、文件与文件夹选择器，以及聊天到 Agentic 的工作区选择。
