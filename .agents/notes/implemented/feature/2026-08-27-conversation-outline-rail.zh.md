# Agent Note：对话在消息列旁获得按轮次的大纲轨

Status: implemented

[English](2026-08-27-conversation-outline-rail.md) | 中文

## 问题

对话一旦变长，回到早前的问题只能靠滚动：消息列没有 pane 内的总览、没有按轮跳转，也看不出每一轮讲过什么。同类助手会在记录旁渲染紧凑的按轮轨道（每问一个刻度、悬停预览、点击跳转），而 fork 没有等价物——最接近的 ui-trajectory 是独立视图 tab 里的调试账本，不是记录导航。

## 决策

新增一个增量会话槽位和一个原生展示插件，按既有分层拆分职责：

- **ui-conversation 拥有座位，插件拥有像素。**常驻会话外壳声明 `conversation.session.outline`（`single`、session 作用域），并把它挂成对话列左缘的零宽穿透覆盖层（内嵌窗格、分屏布局与多窗格分组下隐藏）。新包 `@deepseek-ai/dsh-client-ui-outline` 通过 `slots.inject()` 填充，全部数据来自标准会话套件——没有属主数据、没有新服务、没有会话节点改动，没有任何模型可见物。
- **轮次边界来自行位置，而非提问行。**轮次边界从每条可见行的 `location.turn` 推导；提问（`user`/`steering`）行把截断文本贡献给下一轮的预览，但绝不 gate 推导——编码视图不渲染提问行，且首页历史可能覆盖若干轮而它们的提问落在窗口之外。轮次预览在窗口带提问行时显示问题，否则显示该轮最终一条助手消息的开头文本；刻度宽度按该轮助手文本总长分档，使轨道呈现对话形态。轨道从三轮起才渲染。
- **轨道逐页载入完整对话。**注入面携带会话对象面的 `loadOlder`；尾页窗口打开后，轨道每次只请求一个更早分页，当当前起点处理完后继续，直到历史耗尽。重连或重同步重建窗口时，轨道释放旧分页键；`Session.loadOlder()` 在连续性检查或状态写入前拒绝已被新窗口世代取代的响应。因此自动分页保持串行，过期的第二页也不会隐藏剩余历史。
- **跳转与滚动侦测复用既有锚点。**聊天视图已经给每条已渲染行打上 `[data-conversation-scroll]` 滚动端口下的 `data-chat-anchor-key`；轨道对该 DOM 做滚动侦测（rAF 节流的滚动事件加聊天流的 ResizeObserver）标出阅读线所在轮次，跳转则把该轮行平滑滚动到顶部，走聊天视图既有的滚动记账。
- **符合 fork 约定。**注册、locale 词典、invariant 伴随、包清单、两个 tsconfig 聚合、bundle 行与 web-app 依赖都按新插件清单执行。组件和会话测试覆盖轮次推导、阈值、串行完整历史分页、重同步失效、跳转几何与悬停预览；组装后的浏览器场景会载入、容纳并跳转 88 轮对话。包 README 带有 Model Experience 与已知限制小节并记录了双语配对。

## 后果

- Agentic Coding 与纯聊天对话都获得轨道（座位是会话作用域的外壳 chrome，不区分 agent 预设）；已载入窗口不足三轮时什么都不显示。
- 对话打开后逐步补齐更早分页；每个已载入轮次都有刻度，固定高度的轨道把密集槽位缩至两像素下限，而不是裁掉后续轮次。进行中轮次的预览在其最终助手消息落地后补齐。
- 没有插件时座位什么也不渲染；移除插件的 Loader 行即事务性退场，不触及会话外壳。
- bundle 行默认携带插件。

## 备选方案

- **按位置成比例的 minimap。**否决：流式增长时刻度位置会跳动，而语义锚点（一轮一个）更贴近用户对自己提问的记忆方式。
- **大纲通过自己的 ConversationNodes 读原始会话事件。**否决：标准 chat 快照已经组装出定稿的用户/助手节点；再组装一遍是为零展示收益重复 chat 目标。
- **再加一个 ui-trajectory tab。**否决：账本是带独立视口的检查面，不是 pane 内导航；轨道必须活在它所导航的记录旁边。
