# Agent Note: 工作区之外的原生纯聊天

Status: implemented

[English](2026-08-26-native-plain-chat.md) | 中文

## 问题

Web 产品把每个新对话都视为挂在工作区下的 Agent 工作。只想问一个问题的用户仍要进入项目式导航，并看到暗示文件访问、模式、工具和操作权限的控件。只复用同一个视觉页面而没有能力边界，会让聊天看似无害，却仍保留执行权限。

## 决定

侧边栏提供两个同级主操作：**开始工作**保留原有工作区会话意图，原生 `ui-chat` 插件则通过 `sidebar.primary.action` 贡献**开始聊天**。聊天操作会重新打开已有空白聊天会话，否则以内部 `chat` agent 预设创建一个会话。重复点击由同一个进行中的创建操作承接。

`chat` 预设就是能力边界。它只组装完整的聊天人格，不提供本地执行或项目运行上下文，只开放公开 Web 搜索与读取，并且不出现在工作模式选择器与预设管理中。聊天会话不需要归属工作区，也不依赖 cwd。它继续使用普通会话日志、模型选择、标题、对话流、搜索和历史生命周期，因此产品不会新增平行的聊天数据库。[受限输入决策](2026-08-29-chat-input-and-workspace-return.zh.md)负责聊天上传、联网状态与返回 Agentic Coding 的路径。

工作区浏览器根据持久的 `agentPreset: chat` 会话摘要派生位于最前面的**聊天**分组。对话外壳识别同一个持久事实，移除工作区、agent 预设、权限和模式控件，同时保留模型、附件与消息链路。创建响应会携带该预设，让首次渲染在后续列表刷新前就能正确分类。

**纯聊天**是“小庄的插件”目录中的第 15 项能力。它的开关控制 `ui-chat` 入口；导出定义同时包含本包、内部预设和所有直接扩展的原生源码包，让另一套 DSH 得到完整行为，而不是一个孤立按钮。

## 考虑过的替代方案

**给每个工作会话增加聊天模式。** 可切换的视觉模式仍会保留会话工作区，并可能再次暴露此前组装的工具，也会让同一份历史在两种权限模型间切换。

**另做一套聊天页面和存储模型。** 这样可以隔离界面，但会重复实现对话渲染、流式输出、模型选择、历史、搜索、标题和保留策略，对用户没有额外价值。

**只用提示词约束标准 Agent。** 要求有工具的 Agent 不执行操作并不是可强制的产品边界，而且工作控件仍然可见。

**每次点击都创建新的空白聊天。** 实现很简单，但重复点击会堆积空行，让即时操作显得不可靠。只复用空白聊天可以保留用户有意完成的历史对话。

## 影响

用户不需要选择文件夹或理解 Agent 模式，就能立即进入熟悉的对话。聊天历史仍会持久保存并可搜索，但聊天不能检查或修改电脑；它唯一的外部能力是公开 Web 搜索与读取。内部预设与摘要中的 `agentPreset` 字段成为跨包唯一分类事实；未来若更换聊天组合，必须保留该事实，或引入明确的持久会话类型。

无密钥的 Web 组装快照会点击真实 bundle 中的入口，并验证聊天输入框可写且工作专属控件不存在。定向的运行时、侧边栏、工作区、对话、预设和编排测试覆盖创建、分组、可见性与重复点击行为。
