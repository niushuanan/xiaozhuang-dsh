# Agent Note: 聊天迁移作为一项可安装能力

Status: implemented

[English](2026-08-29-chat-migration-plugin.md) | 中文

## 问题

聊天模式与 DeepSeek 历史导入属于同一个用户任务：把已有对话迁入 DSH，并在没有工作区和执行权限的情况下继续聊天。把它们发布成无关插件，会让安装结果只出现导入页却没有目标聊天体验，或只有聊天入口却没有迁移路径。把导入长期放在目录之外的基础设置里，也会隐藏能力归属并阻断选择性导出。

## 决定

“小庄的插件”目录只呈现一个**聊天迁移**能力。它的运行状态由 `ui-plain-chat` 与 `session-log-download` 两个 Loader 行共同决定，因此聊天入口和导入设置页会一起启停。既有包继续拥有实际行为：聊天模式使用内部 `chat` 预设创建普通会话，`session-log-download` 则解析 DeepSeek 官方 JSON 或 ZIP 导出，并写入普通会话日志、标题、时间、思维过程和投影索引。

导出定义把 `composer-add-menu` 作为安装行，并携带发生过适配的连接、Session controller、聊天 UI、侧边栏、工作区、对话、预设、图标、导入和 `chat` 预设包根。这是安装闭包，不是新的运行包。独立的 `niushuanan/dsh-chat-migration` 仓库是从主仓库已提交定义生成的公开 MIT 单向副本，只包含代码、清单、哈希、安装说明和产品截图，绝不包含导出的对话、账号信息、凭据、设置或本机运行状态。

## 考虑过的替代方案

**把历史导入发布成第二个目录项。** 这会为同一个用户任务暴露两个开关和两个安装选择，并允许目标产品只得到一半体验。

**把导入代码复制到纯聊天包。** 这会重复官方 Session 导出包的解析器、鉴权 Host 路由、持久化集成和设置 UI，使同一个持久化操作出现两个所有者。

**让导入永久开启但留在目录之外。** 这会让能力对插件管理不可见，也让用户无法导出自己正在使用的功能。

## 影响

用户只需安装、启停和导出一个条目，随后就能把历史迁入自己将继续使用的原生聊天目录。关闭该条目也会关闭 Session 导出动作，因为导入与导出共同属于 `session-log-download` 的 Host 与 Client 行；产品接受这一耦合，不为目录展示拆分成熟包。原 `dsh-pure-chat` 仓库继续作为历史发布保留，当前产品链接和后续独立同步统一指向 `dsh-chat-migration`。
