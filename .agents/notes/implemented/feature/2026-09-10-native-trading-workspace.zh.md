# Agent Note: 原生交易工作区

Status: implemented

## Problem

整合产品需要直接提供交易研究，无需单独安装插件或使用另一套应用外壳。上游交易组件面向较新的 DSH API，并接管默认配置和数据路径，与现有工作台存在冲突。

## Decision

[交易工作区](../../../../plugins/trading/README.md)在一个原生产品目录内拥有全部源码、构建、资源和 Cordis patch。侧栏在现有 Web 应用中打开交易工作区。设置和对话草稿使用宿主 API；把图表发给 Agent 会追加草稿并返回对话，不会自动提交消息。

四个可选交易角色补充现有预设。交易数据保存在当前 DSH Home 的 `trading` 目录。默认预设、模型配置和既有对话继续由原有模块管理。整合将角色加载、命令执行、附件和工具结果卡片适配到本地 DSH 版本。

[上游许可和署名](../../../../plugins/trading/UPSTREAM.md)随源码保留。交易组件使用 PolyForm Noncommercial 1.0.0，整合使用范围为个人非商业用途。它随整合仓库交付，没有单独的分发仓库。

## Alternatives considered

**原样安装上游产品包。** 其外壳替换、默认角色覆盖、管理插件和较新的宿主假设会干扰现有产品。整合选择其中的交易能力，并保留本地宿主。

**把交易代码复制进核心包。** 这会让宿主绑定特定产品能力，并破坏按文件夹移除的约定。源码和运行资源因此统一留在原生交易目录。

## Consequences

交易研究共用用户的对话与工作区流程。移除交易目录会移除对应发现和组装，用户数据继续保留。外部数据仍取决于数据源凭据和网络可用性。执行默认使用模拟模式，真实执行继续要求显式审批；实盘下单不属于整合验收范围。

## Testing

自有源码测试覆盖市场研究、策略与知识视图、角色资源、命令分发和草稿附件。原生构建和独立 Web 验收检查侧栏进出、行情图表、自选、设置、角色及草稿传递，不修改运行中产品的 DSH Home。
