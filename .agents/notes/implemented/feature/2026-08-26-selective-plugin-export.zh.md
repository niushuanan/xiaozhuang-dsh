# Agent Note: 把所选小庄插件导出为可由 AI 安装的压缩包

Status: implemented

[English](2026-08-26-selective-plugin-export.md) | 中文

## 问题

Xiaozhuang DSH 已经提供精选插件目录，但用户想把同一项能力装进另一套 DSH 时，仍要自己寻找包代码、推断组装行、避开本机账号状态，并处理目标版本可能存在的破坏性更新。整个仓库对单个插件太宽，直接复制本机 Profile 又可能携带依赖或遗漏原生源码。传递单元必须可以选择、能让安装 AI 读懂，而且即使全选也不能重复复制开发缓存和旧素材版本。

## 决定

现有的**小庄的插件**页面把导出作为目录操作。点击**导出插件**后，列表直接进入行内选择；用户可以逐项选择，也可以全选 15 项能力。全选始终代表全部可导出目录，不受搜索与当前启停状态影响。选择期间不显示运行开关，目录基础包不会导出自己。

原生 `ui-plugin-catalog` Host 只在本机同源入口接受目录 id。每个 id 显式映射仓库或 Profile 包根目录，以及安装该能力需要的 Cordis 行。仓库包提供源码、构建代码、manifest 和 package `files` 字段允许的运行素材；Profile 包提供可移植代码。收集器拒绝路径越界，并排除依赖、Git 元数据、测试、缓存、凭据、设置、会话和历史记录。ZIP 在内存创建，不残留暂存压缩包。

每个压缩包都带有面向人和 Agent 的说明、机器可读 manifest、每个 payload 文件的 SHA-256，以及按插件划分的 payload 根目录。安装 AI 把包与行合入目标，而不是覆盖目标 checkout 或 Profile。直接安装与新版 DSH 结构冲突时，AI 可以窄范围调整插件路径、import、manifest、Slot 和 Cordis 行；它必须保留 manifest 描述的用户行为与目标数据，并记录全部调整。无法安全合并时停止，不能留下已经启用的半安装状态。

## 考虑过的替代方案

**每次都导出整个仓库。** 这可以保证依赖齐全，但失去逐插件选择的意义，传输更大，而且要求安装者自行区分产品代码和无关上游代码。

**只导出本机 Profile 的编译包。** 这对外置插件很快，但缺少破坏性更新后适配原生包所需的 TypeScript，也不能可靠表达 bundle 持有的组装关系。

**提供确定性的一键安装器。** 固定安装器在一个已知 commit 上更快，但早期 DSH 经常改变包布局和扩展契约。压缩包先提供确定事实与直接安装路径，再明确把版本冲突交给安装 AI 处理。

**长期缓存已经生成的压缩包。** 缓存可以减少重复压缩，但会让不同选择和版本持续占用磁盘。内存生成使唯一的持久副本由用户的浏览器下载行为控制。

## 影响

用户可以从已经熟悉的页面传递一个、多个或全部目录能力。压缩包可检查、记录源码 commit，同时提供可安装 JavaScript 与适配源码，又不携带私有运行状态。运行素材白名单让全选导出明显小于仓库开发目录。

任意未来 DSH commit 上的安装不保证完全零修改。这里保证的是输入完整且有界、冲突处理权限明确、用户数据保留、适配过程有记录，并在无法确认兼容时干净停止。以后新增目录能力，需要同时登记其包根目录和组装行。
