# Agent Note: Token 总览深度分析报告

[English](2026-09-20-token-overview-analysis-report.md) | 中文

Status: implemented

## Problem

Token 总览设置页链接的详细报告此前只把面板总量重复成表格和两张堆叠柱状图。采集端其实已经拿到按日、按平台、按模型的完整序列，但"这个月的用量从哪里来"仍要翻原始产物；除当天以外也没有时段节律，因为采集只扫描当天。

## Decision

[Token 总览插件](../../../../plugins/token-overview/package.json)拥有详细报告页面。`assets/report.html` 随插件发布，通过 `plugins/token-overview/report/` 提供；采集目录只提供数据（`data.js`、`hourly.range.js`、`chart.umd.min.js`）。canonical `tokscale-token-report` Skill 继续负责采集、fork 去重、历史恢复、计价和统计口径。

页面在原有总量、表格和图表之上新增十二个分析区块：累计增长与斜率、增长节奏（7 期移动平均与均线环比）、线性外推预测、平台/厂商/Token 类型占比、帕累托集中度、成本结构与缓存收益、日历热力图、星期 × 小时 punchcard 与小时分布、基于局部中位数的尖峰与低谷检测、模型效率气泡与平台效率表、平台份额迁移、模型生命周期区间。

每个区块都在浏览器内用同一份不可变快照重算，并跟随既有的日期、平台和粒度筛选。`hourly.range.js` 为报告范围内每一天每一小时保存 `[...各平台 processedTokens, calls, cost]`。采集端为此按平台各跑一次覆盖报告范围的 Tokscale `hourly` 扫描，并叠加 fork-safe 的 DSH 会话扫描，所以 punchcard 能跟随平台筛选。该产物缺失时，区块回退为"分时数据准备中"提示。

## Alternatives considered

**继续提供 Skill 的 `report.html`，把区块加进 Skill 模板。** Skill 不是仓库 checkout，分析代码将没有可评审的源码、测试和发布副本；两份模板也无法长期保持一致，因此改由插件拥有展示、Skill 保留数据。

**用现有按日产物推导时段节律。** `data.js` 没有逐小时序列；只跑一次全平台小时扫描又会让该区块无法跟随平台筛选。

**为分析单独开一个页面。** 两个页面会把"我花了多少"这个问题拆到两个入口；这些区块属于同一份报告，仍走同一个链接。

## Consequences

插件提供自己拥有的页面，因此插件发布即携带该页面，采集目录仍可随时丢弃。每个采集周期增加五次覆盖报告范围的 Tokscale `hourly` 扫描；它们并行执行，相对既有的 DSH 会话扫描只多几秒。

成本结构与缓存收益来自报告自身的计价行，属于估算；未匹配单价的模型仍以被排除的 Token 数量显示。预测沿用最近 14 期的线性拟合，并在文案中说明。尖峰与低谷同时使用区间分位和局部中位数基线，活跃区间不会把普通波动都当成异常。

## Testing

`test/host.test.mjs` 覆盖报告范围读取、按平台小时归并的 DSH 去重边界，以及发布页面包含全部分析区块和本地数据引用。运行中的插件报告页在真实浏览器上对实时快照做过验收：日期范围、平台筛选、粒度切换、占比与热力图切换、章节跳转均逐项确认，且页面告警区保持为空。
