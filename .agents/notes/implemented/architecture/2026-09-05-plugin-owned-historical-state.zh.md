# Agent Note: 插件声明有界的历史状态兼容

Status: implemented

[English](2026-09-05-plugin-owned-historical-state.md) | 中文

## 问题

已发布的外部插件曾写入不带 `ignorable` 信封的信息型状态。拒绝每条这类记录会让用户在核心升级后无法重开会话。复制任意未知事件可能保留失效的序号引用，丢弃事件则会丢失插件状态。

## 决策

既有 [Session 格式库](../../../../packages/session/session-format/README.zh.md) 接受由 effect 管理的声明，内容为一个外部事件类型、有界版本区间和完整 payload 校验器。拥有者保证状态不依赖 Session 序号、核心生命周期或模型可见语义。历史迁移边只对不在第一方清单中的事件查询声明；带 surface 操作或来源事件引用的信封仍不受支持。获准的状态在后继中保留 payload、时间和相对顺序，并加上 `ignorable: true`。核心包不包含产品插件名。

Teamwork 在自己的可移除插件文件夹中拥有严格的布尔 `active` 校验器。声明覆盖 v0 到 v2，包括 v1-to-v2 的 Assistant chunk 合并。首次读取未标记的历史 Teamwork 状态正文时必须安装该插件。普通 JSONL provider 发布当前代际后，即使移除 Teamwork，同版本读取仍保留该状态。

相邻迁移边也识别已核实的第一方历史元数据。权限来源仍是元数据，绝不改变记录中的权限预设、沙箱模式或审批策略。受支持的旧子代理 descriptor 在版本规范化时保留实际 provider、模型、标签和模式；缺少的可选字段不会获得猜测值。

发布遵循[不可变相邻迁移](2026-08-31-released-session-format-migrations.zh.md)：旧路径、字节和 inode 保持不变，只增加新版代际文件。源文件稳定性使用文件身份和直接字节相等判断，不使用哈希对比。不支持的记录会得到诊断，并且不生成后继。

这是 [alpha 未知事件拒绝规则](2026-08-31-alpha-historical-unknown-event-refusal.zh.md) 的有界例外，不取代其对未声明或语义未经核实记录的拒绝。第一方静态迁移链仍然完整，且不依赖插件组合。

## 考虑过的替代方案

- **让核心代码认识 Teamwork**——会让核心依赖可移除的产品目录，并破坏插件独立拥有其行为的原则。
- **迁移时信任所有未知事件或所有 `ignorable` 标记**——无法证明不透明 payload 在序号位置变化后仍然有效。
- **删除未知状态或重写原始文件**——会丢失用户数据，或移除恢复所需的原始证据。
- **保持无条件拒绝**——会让已知且不依赖序号的插件状态继续阻塞原本有效的历史会话。

## 后果

未标记插件事件的首次转换依赖已安装的拥有者。在转换前删除拥有者，不意味着核心可以猜测其语义。对经过校验的会话转换一次，即可解除当前格式读取的这项依赖；这不承诺降级支持或回退旧代际。

定向测试覆盖两个历史入口版本、状态与消息顺序保留、声明卸载后的当前代际读取，以及未知必需事件和不支持状态继续被拒绝。真实产物检查在不编辑源代际的前提下完成解码、相邻迁移、当前格式编码和重开。普通 JSONL 发布测试继续直接检查源字节与文件身份。
