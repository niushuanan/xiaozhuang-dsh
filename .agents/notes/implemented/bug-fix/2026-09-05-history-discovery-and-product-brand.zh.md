# Agent Note: 升级后的历史查找与产品品牌恢复

Status: implemented

[English](2026-09-05-history-discovery-and-product-brand.md) | 中文

## Problem

相邻 Session 格式升级后，旧对话虽然仍在列表中，却看起来像丢失了。冷会话导航复用了上一代标题和预设，却遗漏最近提问元数据，把活跃对话的时间退回创建日期。工作区浏览器也丢失了此前已交付的渐进展开功能。页面显示上游本地构建标识，而不是社区产品名。

## Decision

会话列表在 `title` 和 `agentPreset` 之外，显式请求版本兼容的 `sessionListMetadata` 上一代缓存行。既有生命周期与行 schema 校验保持不变。这些行只提供导航提示，不作为回放种子；列表不会打开冷会话正文。

冷分支导航无法只从 header 确定继承回放的切点。因此，纯展示缓存路径检查会话标识、创建时间、工作目录、格式方向和已记录的种子标记，但不假装知道该切点；它只返回显式请求且 schema 兼容的行，序号固定为未知值 `-1`。严格检查点与上一代缓存 API 仍要求完整回放身份。这样能让分支名称继续参与标题搜索，而不信任其缓存回放状态。

工作区浏览器恢复每个分组既有的 5 → 10 → 20 条可见窗口。空白草稿不占窗口，拖拽锚点使用同一窗口，关闭分组后重置。这是本地展示状态，不是新的历史数量限制。

v0 迁移还识别已记录的早期 `compact/*` 词汇，并根据既有有序事务重建缺失的压缩与重试关联标识。当前格式校验仍检查字段、引用与关系。标准读取句柄在原件旁发布新一代文件，不改原件、不删除失败事件，也不替换已记录回答。

既有 `plugin-manager` 产品文件夹拥有 Xiaozhuang DSH 侧栏名称与网页标题。侧栏使用已有品牌 slot；layout 提供中性的网页标题 slot，以上游标题 effect 作为回退。移除产品插件后恢复上游标识，不向核心添加产品依赖。

设置导航也因升级后的外壳只识别上游分区 id 而退回通用齿轮。9 个受影响的原生插件各自通过中性的 `settings.section.icon` slot 注册原有图标，以分区 id 匹配，并随自己的生命周期释放。未贡献图标的分区保留外壳默认图标。真实设置入口逐项点击验证图标与页面，Loader 组装回归还验证释放插件不改变其他入口。

## Alternatives considered

**全部重新导入或取消归档。** 两者都不能修复遗漏的元数据。重新导入可能产生重复对话，取消归档则会改变用户有意设置的组织方式。

**打开所有历史正文来填充侧栏。** 这会增加不必要的启动工作量。版本兼容的导航缓存已经包含所需时间。

**把产品名硬编码到核心。** 这违反文件夹级可移除约定，也让上游页面依赖某个特定发行版。

## Consequences

最近活动可以正常查找，不需要重写原始对话或改变正文。与此前一样，导航提示在会话打开前可能陈旧，不能证明回放正确性。真实历史读取与直接消息内容审计分别验证可读性和内容保留。品牌与展开测试覆盖组装后的界面，包括插件释放和分组重置。
