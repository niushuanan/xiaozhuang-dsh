# 原生聊天设计

[English](2026-08-26-native-chat-design.md) | 中文

## 产品约定

侧边栏提供两个同级主操作：**开始工作**保留当前绑定工作区的 Agent 流程，**开始聊天**则立即进入纯对话。聊天不是另一套页面，也不是编辑器模式；它复用现有的对话、历史记录、自动标题、模型、搜索、重命名、分叉与归档界面。

聊天会话显示在工作区文件夹之前独立的**聊天**分组中，不展示文件夹选择、工作区路径、Agent 预设切换、权限选择、斜杠／添加菜单或其他工作专属控件。点击开始聊天时，若已有空白聊天会话则直接复用；否则在 Host 确认创建后选中它，并合并连续点击，避免堆积空白历史。

## 能力边界

`chat` 是随产品发布的内部 Agent preset，也是持久化的会话标记。它的组成只有一段完整的对话人格，不包含 Shell、文件系统、Skills、网页、计划、目标、委派、工作流或任何其他模型工具。界面同样依据会话摘要中持久化的 `chat` preset 切换聊天姿态，因此安全边界不是“把按钮藏起来”。

这个内部 preset 不出现在普通工作模式选择器中，聊天会话也不提供 preset 切换。既有工作会话及其默认 preset 不变。

## 原生插件归属

`ui-chat` 是原生浏览器插件，通过侧边栏属主声明的列表 slot 注入**开始聊天**操作，并负责空白聊天复用与创建／打开编排。`ui-sidebar` 继续持有侧栏几何和**开始工作**操作。客户端运行时透传 Host 已支持的 `agentPreset` 创建参数；对话与工作区浏览器把持久化的 `chat` 标记投影为精简输入栏和独立历史分组。

## 失败与持久化

聊天会话创建失败时保留当前可用界面并记录诊断，不产生幽灵行。会话日志、自动标题和用户数据继续沿用现有持久化链路，不新增第二套聊天数据库或文件夹。空白聊天会话会被复用，因此重复点击不会持续制造空记录。
