# DSH 原生自适应更新设计

[English](2026-08-26-adaptive-update-design.md) | 中文

**日期：** 2026-08-26

**状态：** 已确认实施

## 产品契约

设置入口与页面标题统一使用“自适应更新”，页面不放一句话介绍。用户只需点击一个主操作：当前稳定版 DSH 先进行长时间只读审查，再适配隔离候选版本；只有全部必要验证通过后才允许应用。

原生插件必须在任何官方更新合入之前，先开发在小庄 DSH 本地最新提交上。它的第一次真实任务就是把这个本地产品适配到 `deepseek-ai/deepseek-harness` 最新 master 提交。这个顺序本身就是验收条件，不能先人工合入官方代码，再用一个更新页面代替插件自己的更新过程。

## 稳定执行者与两棵隔离工作树

当前正在运行的本地版本始终是稳定更新执行者。它从精确的本地提交创建一次性审查 worktree，在里面试合并官方提交，盘点变化包、插件、持久化位置、配置和文本冲突，再由稳定版 Headless DSH Agent 做只读语义审查。无论结果如何，审查 worktree 都直接删除。

审查完成后，执行者才创建另一棵候选 worktree，重复固定提交的合并，并让稳定版 Headless DSH Agent 解决冲突、保留本地产品行为。已经损坏的候选版本永远不能反过来承担修复自己的工作。

审查与适配 Agent 使用私有影子 `DSH_HOME`，只复制稳定 Agent 运行所需的最少模型配置、凭据、所有者指令和设置。候选会话、profile 和生成文件不会写进用户真实的 DSH 数据目录。

## 审查报告

持久化报告固定记录本地提交、官方提交、merge base、变化文件数、直接冲突文件、受影响的包和插件，以及 profile 组合、设置、会话持久化、附件和迁移等高风险位置，同时保存稳定 Agent 的语义审查。UI 只展示操作阶段和报告，不把 Git 命令或实现状态暴露成产品概念。

## 候选验证

候选版本必须没有未解决的合并项，并通过依赖安装、仓库差异检查、自适应更新插件定向测试、Host/Client 类型检查、生产构建、Web 回放测试和真实影子 Web 启动。Host 就绪要求 HTTP 服务可用；Client 就绪还要求生成页面与浏览器资源能成功加载。任一失败都不得触碰当前运行产品和真实数据。

## 切换与回滚

外部更新 worker 独立于当前 DSH 进程存活。切换时它先等待当前产品空闲，再停止进程，对真实 DSH 数据创建一个写时复制快照，只把干净的源码 checkout 前移到已验证候选提交，然后按原启动契约重启。如果 launchd 等外部守护程序自行重启 DSH，worker 只观察该进程，不再重复启动。

新版本必须在真实端口同时通过 Host 与 Client 就绪检查，否则 worker 停止它、恢复上一个 Git 提交和数据快照，再启动旧版本。源码更新不会编辑真实 `DSH_HOME`；涉及真实数据的操作只有有上限的快照，以及失败回滚时的整目录原子恢复。

## 存储策略

Git 对象就是版本仓库，插件不会为每个版本复制一套完整 DSH。它只保留当前和上一个提交标识、一个上版本数据的写时复制快照、最新精简报告，不保留已完成的候选 worktree。审查树、失败候选、影子 Home、临时日志和更旧快照由创建它们的操作删除。清理只遍历插件自有控制目录和登记过的 Git worktree。

## 原生产品位置

`ui-adaptive-update` 是一个同时包含 Host 与 Client 的 Cordis 插件。Host 持有本机 API、持久化操作状态、worker 启动、仓库审查和更新生命周期；Client 通过现有 Slot 系统贡献一个设置区，并轮询持久化任务状态。导航图标为手工绘制的 16 px `currentColor` SVG：开放的保护环围住稳定内核，描边和视觉重量与现有图标一致。

## 借鉴来源

设计重新实现而不是热加载 DSH 生态中 MIT 代码的有效思想：借鉴 `amplifthq/oh-my-dsh` 的 current/previous 状态与原子指针恢复，借鉴 `Xrainsmile/DSH-Plugin-Doctor` 的临时 `DSH_HOME` 启动检查和恢复，借鉴 `BotonJ/dsh-windtunnel` 的子进程兼容测试，借鉴 `hezhongtang/dsh-update-copilot` 的先报告风险再行动。它明确不采用进程内 Loader 手术，也不允许超时后继续进入写操作。

## 验收标准

1. 本地小庄 DSH 在合入官方代码前已经包含原生插件。
2. 启动“自适应更新”后，当前 Web 产品在审查、适配、构建和影子启动期间保持可用。
3. 报告在候选适配开始前明确列出固定提交、冲突、受影响插件和语义处理方式。
4. 插件自己把本地产品适配到官方最新 master，并产出验证通过的候选版本。
5. 失败候选永远不会替换当前源码，也不会写入真实 DSH 数据目录。
6. 切换保留 Session、对话、附件、设置、凭据和记忆；真实启动失败时同时恢复代码和数据。
7. 完成后不残留审查/候选 worktree，最多只保留一个上版本数据快照。
