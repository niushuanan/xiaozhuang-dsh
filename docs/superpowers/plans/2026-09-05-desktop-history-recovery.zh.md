# 桌面历史恢复实施计划

[English](2026-09-05-desktop-history-recovery.md) | 中文

> 在当前任务内使用系统化排障、测试驱动开发及完成前验证。用户授权修复、重启、提交和推送；保留无关改动及每个原始会话文件版本。

**目标：** 在用户实际 Safari 桌面应用中恢复完整 Agent 历史，避免升级后的旧页面静默展示不完整记录。

**证据：** 用户报告的会话在原始及 v2 文件中均保留 33 条助手消息、41 次工具调用及 44 条工具结果。Chromium 能展示，实际 Safari Web App 仍为旧标题且只显示初始输入／上下文行；刷新后进入未认证纯文本死胡同。当前静态 index 响应没有显式缓存控制。

**架构：** 不修改会话数据。现有 Connection 提供认证恢复表单；现有 frontend-static 插件禁止 HTML 缓存，并提供轻量重启检查与用户手动重新加载入口。这些行为不依赖产品插件文件夹，也不改变 Agent 执行。

**已确认的回放根因：** 新 Safari 页面能打开 WebSocket，但 util-values 要求 V8 单行原生构造函数文本，导致普通助手数据块被拒绝。改为与当前执行引擎的原生表示比较。浏览器格式测试在修复前失败、修复后通过。真实 Safari 验证恢复了用户报告的四轮对话、展开的 Bash 输出、一条五轮／108 步旧审查记录、更早分页及其子 Agent 报告。原始数据不变。

## 任务

- [x] 按消息内容、工具调用参数和工具结果的顺序核对每对原始／v2 文件；本地记录汇总证据，不比较哈希或写入会话文件。
- [x] 在 `packages/client/connection/tests/browser-auth.host.spec.ts` 和 `packages/host/frontend-static/tests/frontend-static.spec.ts` 增加恢复与新鲜 index 响应的失败 HTTP 测试。
- [x] 在 Connection 实现同源令牌表单，不改变 cookie 校验或在响应中暴露令牌。HEAD 保持无正文，未认证请求保持 401。
- [x] 在 frontend-static 增加 no-store index 和已认证运行实例启动检查。实例变化或登录过期时显示重新加载提示；不自动刷新或修改草稿／历史。用真实 DOM 和模拟网络结果验证输出脚本。
- [x] 运行定向测试、类型检查与构建。告知影响后重启空闲的既有 LaunchAgent；认证并检查实际 Safari 桌面应用，而非只看测试浏览器。验证指定会话及其他 Agent 和导入记录中的回答、已展开工具结果以及刷新。
